# Streamed land battlefield

`streamed_battle_terrain.gd` is the skirmish world controller. One world unit is one metre. The world spans x/z -2500 through +2500, physically reaching 5000 metres on each axis. There are 100×100 possible 50 m chunks; only a 5×5 neighborhood is resident. Each resident tile has a 1 m indexed height grid, rendered mesh and layer-8 triangle collider. Actual colliders are tagged `drivable_ground`; the compatibility `body` member is null. At initialization a 3×3 spawn neighborhood is built; one additional chunk is built per process frame. Old tiles are removed immediately when outside the radius. Ordinary movement has 100 m of prefetched land; arbitrary teleport callers must wait for `is_position_loaded`.

A separate 100×100-cell horizon mesh spans all 5 km (20,000 triangles), without distant collision. This deliberately lowered coarse visual proxy is not evidence that distant physics is active. Far collision is created when the focus arrives. This is a finite land map; callers must stop vehicles at the boundary. It does not implement water or air combat.

## Terrain and seams

Global integer world coordinates index all vertex samples and edits. Every tile uses the same diagonal, boundary height and smooth vertex normal. Edit invalidation includes a one-vertex normal halo, so a pit just inside an edge refreshes neighboring normals even when no boundary height changes. `sample_height` uses the actual mesh triangle interpolation; `sample_normal` supplies a smoothed support normal for vehicle alignment. Imported terrain up to 200 m across can be rasterized at 1 m into the local base, with an 8 m blend at its rectangular boundary. Only the imported source mesh and its own child collision are hidden; other scene objects remain. This approximation does not preserve caves, overhangs or sub-metre source details. Such objects should remain separate props.

## Deformation and engineering

`apply_explosion(position, explosive_mass_kg)` is an explicitly fictional design curve. Radius is clamp(1 + 2*cube_root(mass), 1, 12) metres; depth is clamp(0.10 + 0.32*cube_root(mass), 0.10, 1.4) metres. Zero charge changes nothing. Penetration, projectile velocity and caliber are not inputs. These are game coefficients, not real-world explosive predictions. Mesh resolution may underrepresent pits smaller than about one metre.

`apply_command(position, "dig")` excavates a bounded 0.22 m work increment; `fill` restores 0.30 m toward the original local base. Smooth radial weights apply. Total local excavation is limited to 4 m and fill never rises above the base. Commands queue and return a monotonically increasing `serial`; `terrain_changed` emits that same serial with `collision_pending=false` after commit. Subscribe before calling `flush_updates`, because it emits synchronously. `flush_updates` commits one command and rebuilds all affected loaded tiles (at most four), visual and collision from the same mesh. The next physics tick sees updated physics. Commands on unloaded regions persist in sparse data and become geometry on loading. No full-world mesh is rebuilt. There are explicit queue and sparse-edit budgets; failures return an error rather than deleting older edits. Filling remains available at the edit budget.

`request_engineer_work(actor, target, "dig"/"fill", seconds)` waits for an actual actor within 2.5 m horizontally and 3 m vertically, then emits work increments at 0.5 s intervals. Callers own actual pathfinding/walking. Leaving range pauses work. Freed actors, the canonical infantry brain's dead/disabled state, `person_state.alive=false`, or `engineering_disabled` metadata cancel jobs; an actor-specific `can_engineer_work()` predicate can provide stricter capability checks. Existing arrival-validated construction orders can instead call `apply_command` directly. The terrain API itself never teleports a soldier.

`save_state` and validated atomic `replay_state` preserve sparse world edits. Replay/reset are loading operations and may rebuild all resident tiles; they are not runtime per-frame paths. Source identity prevents applying a save to a different imported terrain. Save dictionaries are caller-owned; persistence to disk belongs to the game's save system.

## Validation and limits

Run `godot --headless --path . --script res://tests/test_streamed_battle_terrain.gd`. Tests inspect actual 5 km geometry, physically load both far corners, check chunk eviction/reload, verify shared edge vertices/normals, compare collider ray height with triangle sampler, and exercise explosion/fill/save/arrival behavior. The test prints measured peak stream-tick CPU time. A bounded number of operations is not a promise of 60 fps on Android: device profiling is still required. The synchronous four-chunk edit transaction trades occasional frame time for consistent seam updates. This implementation has no threaded terrain generation and no disk paging of the edit dictionary.
